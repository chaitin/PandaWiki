# 文档导入功能实施计划

## 一、摘要

为 PandaWiki Java 后端补齐 Admin 前端已存在的文档导入能力，支持三类典型场景：

1. **本地文件批量导入**（txt / md / html / docx / xlsx / pptx / pdf）
2. **URL 抓取导入**（静态网页 → Markdown）
3. **飞书文档导入**（真实调用飞书 Open API）

前端 `AddDocByType` 组件已就绪，会调用 `/api/v1/crawler/*` 与 `/api/v1/file/upload` 接口。本计划在 Java 后端新增 `CrawlerController` 及配套解析服务，使前端流程真正跑通，并与现有 RAG 链路（`nodes` 表 → `EmbeddingService` 向量化）自然衔接。

## 二、现状分析

### 2.1 前端现状

- 入口：`web/admin/src/pages/document/component/AddDocBtn.tsx`
- 核心组件：`web/admin/src/pages/document/component/AddDocByType/index.tsx`
- 流程：
  1. 文件类：`postApiV1FileUpload` 上传 → `postApiV1CrawlerParse` 解析 → `postApiV1CrawlerResults` 轮询 → `postApiV1Node` 创建节点
  2. URL/飞书类：`postApiV1CrawlerParse` 拉取文档树 → 用户勾选 → `postApiV1CrawlerExport` 导出 → 轮询 `results` → `postApiV1Node` 创建节点
- 期望响应格式：`{ success, code, message, data: { id, docs: { value, children } } }`

### 2.2 后端现状

- 已有文件上传：`backend-java/.../FileController.java`（`/api/v1/file/upload`、`/upload/url`、`/upload/anydoc`）
- 已有节点创建：`backend-java/.../NodeController.java`（`POST /api/v1/node`）
- 已有向量链路：`backend-java/.../service/EmbeddingService.kt` + `ChatController.kt`
- **缺少**：`CrawlerController` 及文档解析/抓取/飞书 API 调用能力
- 已有依赖（可直接使用）：
  - `org.apache.tika:tika-core` + `tika-parsers-standard-package`
  - `org.jsoup:jsoup`
  - `com.vladsch.flexmark:flexmark-all`
  - `cn.hutool:hutool-all`

### 2.3 数据库相关表

- `nodes`：文档/文件夹主体，`type=1` 文件夹、`type=2` 文档，`status=0/1/2`
- `knowledge_bases`：知识库，`dataset_id` 当前未在 Java 端使用
- `node_embeddings`：向量表，发布/重建时写入

## 三、实施步骤

### 步骤 1：新增常量与 DTO

**文件**：`backend-java/src/main/java/com/chaitin/pandawiki/consts/CrawlerSource.java`

- 定义枚举 `url`、`file`、`rss`、`sitemap`、`notion`、`feishu`、`dingtalk`、`epub` 等，与前端 `ConstsCrawlerSource` 对齐。
- 提供 `type()` 方法区分 `file` / `url` / `key` 三类来源。

**文件**：`backend-java/src/main/java/com/chaitin/pandawiki/dto/CrawlerDtos.java`

- `ParseReq`：`kb_id`、`crawler_source`、`key`、`filename`、`feishu_setting`、`dingtalk_setting`
- `ParseResp`：`id`、`docs`（嵌套文档树）
- `ExportReq`：`kb_id`、`id`、`doc_id`、`space_id`、`file_type`
- `ExportResp`：`task_id`
- `ResultReq`：`task_id`
- `ResultResp`：`status`、`content`
- `ResultsReq`：`task_ids`
- `ResultsResp`：`status`、`list`
- FeishuSetting：`app_id`、`app_secret`、`user_access_token`、`space_id`
- DingtalkSetting：`app_id`、`app_secret`、`unionid`、`space_id`

### 步骤 2：新增文档解析服务

**文件**：`backend-java/src/main/kotlin/com/chaitin/pandawiki/service/DocumentParseService.kt`

职责：把文件/URL/飞书文档转成 Markdown 文本。

方法：

- `parseLocalFile(path: String): String`
  - 扩展名判断：`.txt/.md/.html` 直接按 UTF-8 读取。
  - `.docx/.xlsx/.pptx/.pdf` 用 Apache Tika `AutoDetectParser` + `BodyContentHandler` 提取正文。
  - 返回 Markdown 或纯文本。
- `parseUrl(url: String): Pair<String, String>`
  - 用 Jsoup 请求 URL（User-Agent、10s 连接超时、30s 读取超时、禁止重定向、50MB 限制）。
  - 提取 `<title>` 作为标题。
  - 提取正文：优先取 `article/main/[role='main']` 区域，降级取 `body`，清洗脚本样式。
  - 用 Flexmark `Html2Markdown` 转成 Markdown。
- `listFeishuDocs(setting: FeishuSetting): CrawlerDocsTree`
  - 调用 `POST https://open.feishu.cn/open-apis/auth/v3/app_access_token/internal` 拿 `app_access_token`。
  - 调用 `POST https://open.feishu.cn/open-apis/document/v1/documents/search` 或 `wiki/v2/spaces/:space_id/nodes` 拉文档列表。
  - 构建文档树返回。
- `exportFeishuDoc(setting: FeishuSetting, docId: String, fileType: String): String`
  - 调用飞书「导出文档为 Markdown」或「获取文档纯文本内容」接口。
  - 返回 Markdown 文本。

### 步骤 3：新增 CrawlerController

**文件**：`backend-java/src/main/java/com/chaitin/pandawiki/controller/CrawlerController.java`

接口：

- `POST /api/v1/crawler/parse`
  - 根据 `crawler_source` 分发：
    - `file`：读取本地 `data/static` 下已上传文件，调用 `DocumentParseService.parseLocalFile`，包装为单节点文档树。
    - `url`：调用 `parseUrl`，包装为单节点文档树。
    - `rss/sitemap/notion`：先抛出 `UnsupportedOperationException` 或返回友好提示；若时间允许可后续扩展。
    - `feishu`：调用 `listFeishuDocs` 返回真实文档树。
    - `dingtalk`：暂不支持，返回提示（可选扩展）。
- `POST /api/v1/crawler/export`
  - 根据 `space_id` / `file_type` 判断是否为飞书：
    - 飞书：调用 `exportFeishuDoc`，生成一个任务 ID 写入内存/Redis，返回 `task_id`。
    - 文件/URL：直接读取内容生成任务，返回 `task_id`。
- `POST /api/v1/crawler/results`
  - 根据 `task_ids` 查询内存/Redis 中的任务结果。
  - 返回 `status`（`pending/in_process/completed/failed`）和 `content`。

任务存储：使用 ConcurrentHashMap + 定时清理（简单内存方案），或复用 Redis。

### 步骤 4：扩展 FileController（可选但推荐）

**文件**：`backend-java/src/main/java/com/chaitin/pandawiki/controller/FileController.java`

- 当前上传返回 `{key, filename}`。
- 确认前端 `postApiV1FileUpload` 使用的字段名一致，无需改动。
- 如需支持 URL 导入文件（`/api/v1/file/upload/url`），已存在，保持不动。

### 步骤 5：RAG 链路适配

**无需新增代码**，但需在流程中确认：

- `NodeController.create` 写入的 `nodes` 记录 `status=1`（更新未发布）。
- 用户在 Admin 发布知识库（`POST /api/v1/knowledge_base/release`）后，`nodes.status` 变为 `2`。
- 问答时 `EmbeddingService.ensureIndexed()` 会对 `status=2` 的文档做向量化。
- 导入完成后建议自动/提示用户发布，以便 RAG 生效。

### 步骤 6：前端适配（最小改动）

**文件**：`web/admin/src/pages/document/component/AddDocByType/util.ts`

- 当前 `flattenCrawlerParseResponse` 已能处理嵌套文档树。
- 主要确认 `CrawlerController` 返回的 `docs.value.id/title/summary/file/file_type` 字段与前端 `AnydocValue` 一致。
- 若后端返回单文件节点 `file=true`，前端会走导出 → 创建文档节点流程。

### 步骤 7：配置与凭证

**文件**：`backend-java/src/main/resources/application.yml`

- 新增（可选）飞书默认配置占位：
  ```yaml
  panda:
    crawler:
      feishu:
        app-id: ${FEISHU_APP_ID:}
        app-secret: ${FEISHU_APP_SECRET:}
  ```
- 注意：前端表单会传 `app_id/app_secret/user_access_token`，后端优先使用请求中的值。

**需要你准备**：

- 飞书开放平台应用：
  - 创建企业自建应用
  - 开启「云文档」权限：`docs:document:readonly`、`wiki:wiki:readonly`、`drive:drive:readonly` 等
  - 获取 `App ID`、`App Secret`
  - 通过 OAuth2 获取 `user_access_token`（可使用飞书「获取 user_access_token」调试工具）

### 步骤 8：文档与毕设讲解素材

**文件**：`others/bishe.md`

- 新增一节「文档导入与 RAG 数据准备」。
- 讲解点：

  - 三类来源的技术差异：本地文件（格式解析）、URL（HTML 清洗）、飞书（OAuth2 + Open API）。

## 四、验收标准

1. **本地文件导入**：在 Admin「创建文档 → 通过离线文件导入」选择 `.md`/`.docx`/`.pdf`，能成功创建文档节点并查看内容。
2. **URL 导入**：输入 `https://xxx`，能拉取标题和正文，创建节点。
3. **飞书导入**：输入正确凭证后，能列出云文档，勾选后导入为节点。
4. **RAG 生效**：导入并发布后，App 前台问答能引用到新文档内容。

## 五、实施顺序建议

1. 先实现本地文件导入（最快验证 Tika + 接口格式）。
2. 再实现 URL 导入（验证 Jsoup + HTML 转 Markdown）。
3. 最后实现飞书导入（需要真实凭证调试 API）。
4. 全程边做边更新 `oprater.md` 与 `bishe.md`。

## 六、风险与兜底

- **飞书凭证拿不到**：先用飞书「开放平台的 API 调试工具」生成临时 token；若仍无法获取，改为模拟数据 + 接口占位，答辩时讲清替换点。
- **URL 正文提取效果差**：先实现简单提取，后续可接入 Readability 算法或 Jina AI Reader 作为升级点。
- **文件解析乱码**：Tika 已内置编码探测，md/txt 显式按 UTF-8 读取。
